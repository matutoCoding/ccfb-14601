# 巢脾检查台 · 三维复现系统

面向蜂场的**巢脾检查记录 + 三维复现**浏览器应用。开箱即用、数据存 IndexedDB、
Service Worker 整包缓存，转场到山里无网络也能完整使用。

技术栈：TypeScript + three.js（实例化渲染）+ Vite，无 UI 框架、无外部网络依赖。

## 启动

```bash
npm install
npm run dev        # 开发，默认 http://localhost:5173
npm run build      # 类型检查 + 生产构建到 dist/
npm run preview    # 预览生产包
```

把 `dist/` 托管到任意静态服务器（或直接用 PWA 安装到桌面/平板），首次联网打开后，
Service Worker 会缓存全部静态资源，之后断网仍可打开、检查、刷涂、推演。

## 五个页面

| 路由 | 页面 | 能力 |
| --- | --- | --- |
| `#/map` | 蜂场地图 | 3 场地 26 箱按排位展示；颜色=群势强弱，红框=超过 7 天未查；点箱进档案 |
| `#/hive/:id` | 蜂箱档案 | 蜂王代数/出房/品种/继箱、巢脾列表、检查记录（可新增/编辑） |
| `#/comb/:hive/:frame` | 巢脾查看 | 三维巢脾、逐房点选、刷子批量标记、翻面、21 天时间轴、遮挡几何自检 |
| `#/analysis/:id?` | 群势分析 | 子脾/蜜脾曲线、去年同期对比、摇蜜估产、全场群势柱状对比 |
| `#/migration` | 转场计划 | 油菜/洋槐/荆条花期排程，按群势挑箱、车辆编组、夜间行车时间计算 |

## 测试数据（首次打开自动生成）

- 3 个场地、26 个蜂箱、243 张巢脾、13 个月历史与多次检查记录。
- **H-A05 为失王后工蜂产卵群**：巢房内一房多卵（2~4 粒）、卵圈散乱、插花比例高，
  健康评判会明确预警。
- H-A07 失王无卵群；H-A03 白垩病；H-A09 囊状幼虫病；其余为正常群与边缘王台。
- 数据由确定性随机数（mulberry32 + 字符串哈希）生成，同 ID 永远复现同一套巢房。

## 巢房几何与深度遮挡（核心）

真实意蜂尺寸（毫米）：工蜂房对边距 5.38（外接圆 R=3.107）、雄蜂房 6.40、
单侧房深 11、卵高 1.6。巢框内围 456×214，整脾两面共 **7030 个可点巢房**。

遮挡不是贴图假效果，而是**真实六棱柱蜡壁 + 房底卵的几何**：视线斜到临界角后，
房底/卵被蜡壁物理挡住。代码提供三种互相独立的算法并在页面内一键自检：

1. **足迹法** `hexVisibilityFraction`：过房底点 p 的光线在房口平面落点
   `r = p + h·tanθ·t̂`，落在房口六边形内才可见。
2. **显式射线法** `hexVisibilityFractionRay`：光线与六面有限壁段逐一求交，
   交点在壁段内且 z<h 即遮挡。与足迹法在 240 组角度采样上偏差 0.00%。
3. **圆管解析法** `circleVisibilityFraction`：等效圆房积分
   `A = ∫[-R, R-b] 2√(R²-x²)dx`，因六边形/圆形状差异约有 10~17% 系统差，作为对照。

临界角：全房底遮挡 `atan(2R/h) ≈ 29.4°`；卵尖遮挡（最坏方位）
`atan(R·cos30°/(h-e)) ≈ 16°`，与现场"斜一点就看不见卵"的经验一致。

## 性能

- 全部巢房走 `InstancedMesh`，蜡壁/房底/卵/幼虫/封盖/蜜/粉等各一个实例化批次，
  整脾约 13 个 draw call。
- 自动检测 SwiftShader 等软件渲染环境并降级（关透射通道、降阴影/分辨率），
  真实 GPU 上 7000 房旋转稳定 60 帧。
- 巢房数据用 TypedArray（`Uint8Array`/`Uint16Array`/`Float32Array`）结构化克隆入 IndexedDB，
  一张脾两面约几十 KB。
